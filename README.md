# verinoo-node

**Rust node for [Verinoo](https://verinoo.com) — an AI chain network with
optimistic inference verification.**

Status: **testnet node with a working verifiable-inference vertical slice.**
Single- and multi-validator testnets run, and inference tasks are executed by
consensus against a real (small) model with on-chain receipts and a
verification endpoint. Consensus is still round-robin with no BFT finality.
Models come from the compiled-in reference classifier plus operator graph models
loaded from `VNN_MODEL_DIR`. Dense/relu/softmax classifiers convert from ONNX
(`onnx-import`) and GGUF (`gguf-import`, dequantising Q4/Q5/Q8); transformer
checkpoints — attention, arbitrary tokenizers, sampling — cannot run yet. See
[`docs/product.md`](docs/product.md) for the product and
[`docs/readiness.md`](docs/readiness.md) for the matrix, and
[`docs/pilot.md`](docs/pilot.md) for the design-partner proof summary.

| Crate | Purpose |
|---|---|
| `types` | Canonical codec, tx model — byte-parity with the reference client |
| `conformance` | Golden-vector tests generated by the TS oracle |
| `state` | RocksDB-backed state (accounts, models, tasks, nodes, validators) |
| `exec` | Validation, gas market, block production/application, dispute ops |
| `network` | libp2p gossipsub block/tx propagation + mDNS |
| `model` | `intent-classifier-v1`: deterministic Q16.16 inference + trainer |
| `runtime` | integer-only graph runtime for operator-supplied models |
| `onnx` | ONNX classifier → runtime graph (`onnx-import`), with float/integer parity |
| `gguf` | GGUF dense classifier → runtime graph (`gguf-import`), Q4/Q5/Q8 dequantisation |
| `zk` | Q16.16 op vectors and conformance against the WASM runtime |
| `node` | Binary: wiring, RPC API, wallet CLI, systemd/deploy assets |

The TypeScript repository ([iguha0/Verinoo](https://github.com/iguha0/Verinoo))
is the **reference client**: its engine defines validation semantics, and its
test-suite exports the golden fixtures this workspace reproduces exactly. See
`crates/conformance/fixtures/`.

## Live testnet

Prebuilt `x86_64` Linux binary:
<https://github.com/iguha0/verinoo-node/releases/tag/v0.1.0-testnet>

The `/v1` API is deployed behind **https://verinoo.com** (single validator,
testnet, no SLA):

```bash
curl -s https://verinoo.com/v1/models | jq
verinoo-node wallet generate --output key.json
ADDR=$(jq -r .address key.json)
curl -s -X POST https://verinoo.com/faucet \
  -H 'content-type: application/json' -d "{\"address\":\"$ADDR\"}"
sleep 12
verinoo-node infer --key-file key.json \
  --input "my parcel was never delivered" --node https://verinoo.com
./scripts/verify.sh <taskId> --node https://verinoo.com
```

## Run a node

```bash
cargo build --release --locked

VNN_KEY_SEED="$(openssl rand -hex 32)" \
VNN_VALIDATOR=1 \
VNN_API_PORT=7100 \
VNN_P2P_PORT=7101 \
./target/release/verinoo-node
```

A lone validator authorizes itself, so blocks start immediately. **To run more
than one node you must give every node the same full set**, or peers will
reject each other's blocks:

```bash
# derive each node's address before starting it
verinoo-node address --seed <that-node's-VNN_KEY_SEED>

VNN_VALIDATORS=ai_aaaa...,ai_bbbb... VNN_SEEDS=/ip4/203.0.113.10/tcp/7101 ...
```

Reproduce a two-validator consensus + independent-verification run locally:

```bash
./scripts/demo-2node.sh   # 11 checks: replication, identical result hash, verify on both nodes
```

| Variable | Default | Notes |
|---|---|---|
| `VNN_DB` | `./vnn-data` | RocksDB path |
| `VNN_API_PORT` | `7100` | HTTP RPC |
| `VNN_P2P_PORT` | `7101` | libp2p TCP |
| `VNN_KEY_SEED` | *(empty)* | **required** for validators; unique per node |
| `VNN_VALIDATOR` | `false` | produce blocks |
| `VNN_VALIDATORS` | self if validator | active set, comma-separated |
| `VNN_SEEDS` | *(none)* | `/ip4/<host>/tcp/<port>` peers |

| Endpoint | Purpose |
|---|---|
| `GET /health` | liveness + head age + validator count |
| `GET /status` | chain id, height, head hash, mempool depth |
| `GET /metrics` | height, head age, mempool, validator count |

| `GET /mempool` | mempool depth |
| `POST /tx` | validate, enqueue, and gossip a signed tx |

| `GET /v1/models` | models this node executes, with weights hash |
| `POST /v1/infer` | submit a signed inference transaction |

| `GET /v1/verify/:id` | recompute the output and compare with the chain |
| `GET /v1/usage/:addr` | per-address metering (JSON) |
| `GET /v1/usage/:addr/csv` | metering export for invoicing |

### Inference

Inference tasks are executed **by consensus**: every node applying a block
re-runs the model over the task input in integer arithmetic, so the output is
part of state transition rather than the producer's claim. Each finished task
gets a receipt anchored to the block that carried it.

```bash
cargo build --workspace
./scripts/demo.sh    # local node → faucet → inference → verification

# or manually, against a running node
verinoo-node infer --key-file key.json --input "my parcel was never delivered"
curl -s localhost:7100/v1/verify/<taskId> | jq '{verified, output}'
```

The reference model (`intent-classifier-v1`, 8,196 parameters) is trained from
the committed corpus with `cargo run --release -p verinoo-model --bin train`.

Additional models are loaded from `VNN_MODEL_DIR` (default `./models`) and
executed in consensus the same way. They must be dense/relu/softmax graphs over
the hashed-unigram featuriser; see [`docs/runtime.md`](docs/runtime.md) for the
format and `models/acme-support-v1.graph.json` for a working example. Every
node must load the same set — `/v1/models` exposes the set and its hash.

```bash
cargo run -p verinoo-model --bin export -- \
  --model-id acme-support-v1 --out models/acme-support-v1.graph.json
verinoo-node infer --model acme-support-v1 --input "my parcel was never delivered"
```
