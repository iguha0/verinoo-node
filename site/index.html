A log is not a receipt.

A database row can be edited. It does not prove the input, the weights, or the computation that produced an answer.

01

Logs are not evidence.

An operator can change a row, redeploy a model, or lose the original request. The answer survives; the proof does not.

02

Weights drift silently.

A retrain changes every answer. Without a weights hash, you cannot say which parameters produced the output an auditor is asking about.

03

Disputes have no artifact.

When a customer or regulator challenges a decision, a screenshot is not enough. You need a result that can be recomputed independently.

The block is the proof.

The model runs inside state transition, in integer arithmetic, on every node. The output is consensus state, not a claim attached to a response.

  1. 01

    Encrypt the input

    The client encrypts to the validator network key. Blocks and APIs carry ciphertext, not the request.

    X25519 + ChaCha20-Poly1305
  2. 02

    Submit a transaction

    A signed request enters the mempool. The transaction commits to the input and the exact model id.

    POST /v1/infer
  3. 03

    Re-execute on every node

    During block application, every node runs the same Q16.16 forward pass and derives the same bytes.

    apply_block → resultHash
  4. 04

    Anchor the receipt

    The block signature binds the result, the weights hash and the input commitment. Anyone can recompute it.

    GET /v1/verify/:id

What is live. What is not.

The honest version, because a technical buyer will test it in the first call.

Live today

  • liveConsensus re-execution of dense, relu and softmax classifiers
  • liveONNX and GGUF import, including Q2_K to Q6_K
  • liveEncrypted inputs, receipts and /v1/verify
  • liveAPI keys, quotas, metering and CSV export
  • liveCatch-up sync, backups and TypeScript/Python SDKs

Not yet

  • not yetTransformer and LLM runtime. Attention is a prototype.
  • not yetBFT finality. Today the producer signature is the finality.
  • not yetZK proofs. Verification is re-execution, not a succinct proof.
  • not yetOperator-blind privacy. Validators can decrypt inputs.
  • not yetAutomatic HA, snapshot sync and token settlement.
