# verinoo-node v0.11.0-testnet

Released 2026-11-18 · testnet · AGPL-3.0

This release adds an opt-in BFT finality certificate layer over the existing
block chain. It is a real quorum implementation, not a design note: validators
sign prevotes and precommits over validated blocks, collect a 2/3+1
certificate, persist finality, and record equivocation evidence. The live
testnet is single-validator and now runs with `VNN_CONSENSUS=bft`; a local
four-validator cluster finalized the same head at height 20 with three peers.

> **Scope — do not overclaim**
>
> Finality certificates are implemented. Block production remains
> single-producer round-robin: there is no view-change for an offline leader,
> the head is still optimistic (it can advance before a certificate), and there
> is no certificate-aware catch-up, slashing or automatic validator removal.
> A mixed legacy/BFT multi-validator network will not finalize. The live
> testnet is single-validator, where quorum is one.

## What changed

- **`crates/consensus`**: signed prevotes, precommits, proposals, commit
  certificates, quorum verification, equivocation evidence, and a
  deterministic round/lock state machine with 26 tests.
- **Gossip**: `verinoo/proposals/1`, `verinoo/votes/1` and
  `verinoo/evidence/1` topics with payload caps and a two-node propagation test.
- **Node**: `VNN_CONSENSUS=legacy|bft`. In `bft` mode, a validator votes after
  applying a block and checking its state root; a 2/3+1 precommit certificate
  finalizes it. Certificates and own votes are persisted; `/status` exposes
  `consensus`, `finalizedHeight` and `finalizedHash`.
- **Evidence**: conflicting votes at the same `(height, round, kind)` produce
  stored, deduplicated equivocation evidence. No slashing or automatic removal.
- **Tests**: 274 Rust tests, 17 TypeScript, 15 Python, 24 importer, 20 Stripe;
  clippy clean. Four-node live proof: all nodes at height 20, finalized height
  20, identical finalized hash, three peers each.

## Enable and upgrade

v0.11.0 keeps the v2 block format from v0.10.0. The release is drop-in; no block
format migration is required. Finality is opt-in:

```bash
VNN_CONSENSUS=bft VNN_VALIDATOR=true VNN_VALIDATORS=ai_...,ai_...
```

- The live single-validator node is upgraded with `VNN_CONSENSUS=bft`.
- For a multi-validator network, upgrade every validator and enable `bft` in the
  same window. A legacy node ignores vote topics and cannot contribute to a
  quorum; a mixed set will not finalize.
- Keep the validator set identical on every node. The finality manager sorts and
  deduplicates addresses; quorum is `floor(2N/3)+1`.
- `/status` shows `finalizedHeight`/`finalizedHash`; a gap between head and
  finalized height is expected until the quorum certificates arrive.
- Rollback to v0.10.0 legacy is possible because the block format is unchanged,
  but finality certificates become advisory and are not replayed.

## Verification

- 4-validator local cluster (all online): height 20, finalized 20, same hash,
  3 peers each.
- Single-validator live test: block finalized immediately in `bft` mode.
- Core tests cover 4-validator finality, one Byzantine/equivocating voter,
  timeout/nil votes, locks, own-vote replay and certificate rejection.
- Existing claims-triage, sampling, batch/SSE, policy and snapshot tests remain
  green.

## Artifact

`verinoo-node-v0.11.0-testnet-x86_64-linux.tar.gz` contains the stripped binary,
seven small models, the demo/import/billing/snapshot/release scripts, both SDKs,
`node.env.example`, `LICENSE`, `README.txt`, and selected docs. TinyStories-1M
and DistilGPT-2 weights are not included.

## Still not claimed

- **No view-change/offline-leader liveness.** A missed leader still stalls the
  chain as before; BFT mode adds certificates, not a new proposal schedule.
- **No commit-only-after-finality gating.** The head is optimistic; finality is
  tracked separately.
- **No certified catch-up/finalized sync.** A late node replays blocks and
  starts participating in new finality; historical certificates are not served
  over RPC.
- **No slashing, automatic removal or validator-set changes.** Evidence is
  recorded only.
- **No trustless multi-operator claim.** The live network is one operator and
  one validator; BFT certificates need independent validators to be meaningful.
- **No GPU, runtime batching, token streaming, output moderation or LLaMA
  import** beyond the v0.10.0 surface.
